OpenMU Monolithic Conversion Guide
===================================

CURRENT STATUS:
OpenMU is ALREADY running as a monolithic application in the all-in-one deployment!
However, it still uses external PostgreSQL database. Here's how to make it TRULY monolithic.

CURRENT ARCHITECTURE:
- All game services run in single process (ConnectServer, GameServer, ChatServer, etc.)
- External PostgreSQL database (separate container)
- Nginx proxy (separate container)

TARGET MONOLITHIC ARCHITECTURE:
- Single executable with embedded database
- No external dependencies
- Self-contained deployment

================================================================================
OPTION 1: EMBEDDED DATABASE (RECOMMENDED)
================================================================================

STEP 1: MODIFY STARTUP TO USE IN-MEMORY DATABASE
The OpenMU already supports in-memory mode with -demo flag.

Create a custom startup configuration:

```csharp
// File: src/Startup/MonolithicProgram.cs
namespace MUnique.OpenMU.Startup;

public sealed class MonolithicProgram : Program
{
    public static async Task Main(string[] args)
    {
        // Force in-memory database for true monolithic deployment
        var monolithicArgs = args.Concat(new[] { "-demo" }).ToArray();
        
        // Disable admin panel for pure monolithic mode (optional)
        // var monolithicArgs = args.Concat(new[] { "-demo", "-adminpanel:disabled" }).ToArray();
        
        await Program.Main(monolithicArgs);
    }
}
```

STEP 2: CREATE MONOLITHIC DOCKERFILE
Create a new Dockerfile for monolithic deployment:

```dockerfile
# File: Dockerfile.monolithic
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS base
WORKDIR /app
EXPOSE 80
EXPOSE 44405
EXPOSE 44406
EXPOSE 55901-55906
EXPOSE 55980

FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Copy project files
COPY ["src/Startup/MUnique.OpenMU.Startup.csproj", "src/Startup/"]
COPY ["src/", "src/"]

# Restore dependencies
RUN dotnet restore "src/Startup/MUnique.OpenMU.Startup.csproj"

# Build application
COPY . .
WORKDIR "/src/src/Startup"
RUN dotnet build "MUnique.OpenMU.Startup.csproj" -c Release -o /app/build

FROM build AS publish
RUN dotnet publish "MUnique.OpenMU.Startup.csproj" -c Release -o /app/publish

FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .

# Set environment for monolithic mode
ENV ASPNETCORE_URLS=http://+:80
ENV OPENMU_MODE=monolithic

# Start in demo mode (in-memory database)
ENTRYPOINT ["dotnet", "MUnique.OpenMU.Startup.dll", "-demo", "-autostart"]
```

STEP 3: CREATE MONOLITHIC DOCKER COMPOSE
Create simplified docker-compose for monolithic deployment:

```yaml
# File: docker-compose.monolithic.yml
version: '3.8'

services:
  openmu-monolithic:
    build:
      context: .
      dockerfile: Dockerfile.monolithic
    container_name: openmu-monolithic
    ports:
      - "80:80"           # Admin Panel
      - "44405:44405"     # Connect Server 1
      - "44406:44406"     # Connect Server 2
      - "55901:55901"     # Game Server 1
      - "55902:55902"     # Game Server 2
      - "55903:55903"     # Game Server 3
      - "55904:55904"     # Game Server 4
      - "55905:55905"     # Game Server 5
      - "55906:55906"     # Game Server 6
      - "55980:55980"     # Chat Server
    environment:
      - ASPNETCORE_ENVIRONMENT=Production
      - OPENMU_MODE=monolithic
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:80"]
      interval: 30s
      timeout: 10s
      retries: 3
```

STEP 4: BUILD AND DEPLOY MONOLITHIC VERSION
```bash
# Navigate to OpenMU directory
cd /workspaces/HMI/OpenMU

# Build monolithic image
docker build -f Dockerfile.monolithic -t openmu-monolithic .

# Run monolithic version
docker-compose -f docker-compose.monolithic.yml up -d
```

OPTION 2: SQLITE EMBEDDED DATABASE
================================================================================

For persistent data with embedded database, use SQLite:

STEP 1: MODIFY CONNECTION SETTINGS
Create SQLite connection configuration:

```xml
<!-- File: src/Persistence/EntityFramework/ConnectionSettings.sqlite.xml -->
<?xml version="1.0" encoding="utf-8"?>
<ConnectionSettings xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema">
  <Connections>
    <ConnectionSetting>
      <ConnectionString>Data Source=openmu.db</ConnectionString>
      <DatabaseName>OpenMU</DatabaseName>
      <DatabaseSchemaName>data</DatabaseSchemaName>
    </ConnectionSetting>
  </Connections>
</ConnectionSettings>
```

STEP 2: CREATE SQLITE STARTUP
```csharp
// File: src/Startup/SqliteMonolithicProgram.cs
namespace MUnique.OpenMU.Startup;

public sealed class SqliteMonolithicProgram
{
    public static async Task Main(string[] args)
    {
        // Set SQLite connection
        Environment.SetEnvironmentVariable("OPENMU_CONNECTION_FILE", "ConnectionSettings.sqlite.xml");
        
        // Add SQLite-specific arguments
        var sqliteArgs = args.Concat(new[] { "-autostart" }).ToArray();
        
        await Program.Main(sqliteArgs);
    }
}
```

STEP 3: SQLITE DOCKERFILE
```dockerfile
# File: Dockerfile.sqlite
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS base
WORKDIR /app
EXPOSE 80

FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src

# Install SQLite
RUN apt-get update && apt-get install -y sqlite3

COPY ["src/Startup/MUnique.OpenMU.Startup.csproj", "src/Startup/"]
COPY ["src/", "src/"]

RUN dotnet restore "src/Startup/MUnique.OpenMU.Startup.csproj"

COPY . .
WORKDIR "/src/src/Startup"
RUN dotnet build "MUnique.OpenMU.Startup.csproj" -c Release -o /app/build

FROM build AS publish
RUN dotnet publish "MUnique.OpenMU.Startup.csproj" -c Release -o /app/publish

FROM base AS final
WORKDIR /app
COPY --from=publish /app/publish .

# Copy SQLite connection settings
COPY ["ConnectionSettings.sqlite.xml", "./"]

# Create data directory for SQLite database
RUN mkdir -p /app/data
VOLUME ["/app/data"]

ENV ASPNETCORE_URLS=http://+:80
ENTRYPOINT ["dotnet", "MUnique.OpenMU.Startup.dll", "-autostart"]
```

================================================================================
OPTION 3: SINGLE EXECUTABLE (MOST MONOLITHIC)
================================================================================

Create a single executable with everything embedded:

STEP 1: MODIFY PROJECT FILE
Add to MUnique.OpenMU.Startup.csproj:

```xml
<PropertyGroup>
  <PublishSingleFile>true</PublishSingleFile>
  <SelfContained>true</SelfContained>
  <RuntimeIdentifier>linux-x64</RuntimeIdentifier>
  <PublishTrimmed>true</PublishTrimmed>
  <IncludeNativeLibrariesForSelfExtract>true</IncludeNativeLibrariesForSelfExtract>
</PropertyGroup>
```

STEP 2: BUILD SINGLE EXECUTABLE
```bash
cd /workspaces/HMI/OpenMU/src/Startup

# Build single executable
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -o ./publish-monolithic

# The result will be a single executable: MUnique.OpenMU.Startup
```

STEP 3: CREATE DEPLOYMENT SCRIPT
```bash
#!/bin/bash
# File: deploy-monolithic.sh

# Build single executable
cd /workspaces/HMI/OpenMU/src/Startup
dotnet publish -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -o ./publish-monolithic

# Copy to deployment location
cp ./publish-monolithic/MUnique.OpenMU.Startup /usr/local/bin/openmu-server
chmod +x /usr/local/bin/openmu-server

# Create systemd service
cat > /etc/systemd/system/openmu-monolithic.service << EOF
[Unit]
Description=OpenMU Monolithic Game Server
After=network.target

[Service]
Type=simple
User=openmu
WorkingDirectory=/opt/openmu
ExecStart=/usr/local/bin/openmu-server -demo -autostart
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

# Enable and start service
systemctl enable openmu-monolithic.service
systemctl start openmu-monolithic.service
```

// In Program.cs, modify CreateHostAsync method
private async Task<IHost> CreateHostAsync(string[] args)

    var builder = WebApplication.CreateBuilder(args);

        options.ListenAnyIP(443, listenOptions =>

================================================================================

| Option | Database | Dependencies | Size | Persistence | Complexity |
|--------|----------|--------------|------|-------------|------------|
| Current All-in-One | PostgreSQL | 3 containers | Medium | Yes | Low |
| In-Memory Demo | In-Memory | 1 container | Small | No | Very Low |

| Single Executable | In-Memory | None | Very Small | No | Very Low |
| Embedded Web | In-Memory | 1 container | Small | No | Low |

RECOMMENDED APPROACH
================================================================================

For TRUE monolithic deployment, I recommend OPTION 3 (Single Executable):

STEP 1: Quick Implementation
```bash
cd /workspaces/HMI/OpenMU

# Create monolithic deployment directory
mkdir -p deploy/monolithic

# Copy the single executable build script
cat > deploy/monolithic/build-monolithic.sh << 'EOF'
#!/bin/bash
set -e

echo "🚀 Building OpenMU Monolithic Executable..."

cd ../../src/Startup

# Build single executable
dotnet publish -c Release -r linux-x64 \
  --self-contained true \
  -p:PublishSingleFile=true \
  -p:PublishTrimmed=true \
  -o ../../deploy/monolithic/output

echo "✅ Monolithic executable built successfully!"
echo "📁 Location: deploy/monolithic/output/MUnique.OpenMU.Startup"
echo "🎮 Run with: ./MUnique.OpenMU.Startup -demo -autostart"
EOF

chmod +x deploy/monolithic/build-monolithic.sh

# Build it
./deploy/monolithic/build-monolithic.sh
```

STEP 2: Run Monolithic Version
```bash
cd deploy/monolithic/output

# Run the monolithic server
./MUnique.OpenMU.Startup -demo -autostart

# Access admin panel at http://localhost
# All game services running in single process
# No external dependencies
```

================================================================================
BENEFITS OF MONOLITHIC APPROACH
================================================================================

✅ ADVANTAGES:
- Single executable deployment
- No external database dependencies
- Faster inter-service communication
- Lower memory footprint
- Simplified deployment and maintenance
- No network latency between services
- Easier debugging and monitoring

⚠️ CONSIDERATIONS:
- In-memory data (lost on restart)
- Single point of failure
- Harder to scale horizontally
- All services share same resources
